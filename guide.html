01 / The easiest way to update your portfolio

  1. Open the content editor. Fill in your profile and add entries to the sections you want.
  2. Select Preview draft to see your changes. Drafts stay in this browser and are not published or shared.
  3. Select Download content.js. Replace the existing content.js in your website folder with the downloaded file. If your browser names it content (1).js, rename it to content.js.
  4. Upload the replacement to your GitHub repository and commit. Once GitHub Pages is enabled, commits to its configured source update the live site.

You can also edit content.js in a text editor. It is the single source of truth for portfolio text, links, section visibility, and ordering.

Add a profile photo or résumé

Place a photo at assets/profile.jpg and a résumé at assets/resume.pdf. Enter those relative paths in the editor’s Profile tab. You can use other filenames too. Upload the actual files along with your content changes. The résumé link appears automatically when a path is set.

Use the editor through the hosted preview or a local web server. For a local preview, run python3 -m http.server 8000 inside the extracted website folder, then open http://localhost:8000. Directly opening files may limit browser draft storage.

03 / Add, hide, and rearrange sections

In the editor, open Sections & more. Use the checkbox beside a section to show or hide it, and the arrow buttons to reorder it. Disable Show empty sections when you want to show only populated sections.

Choose Add custom section for awards, publications, volunteering, or anything else. Give it a title and description, then add entries with a title, details, and an optional link. It joins the navigation automatically.

Custom IDs must start with custom- and use lowercase letters, digits, and hyphens. The editor handles this for you.

04 / Publish at your GitHub Pages address

To use your requested address, padmakarbudda.github.io, the repository must be named padmakarbudda.github.io.

  1. Sign in to GitHub. Create a public repository named padmakarbudda.github.io, or open that repository if it already exists.
  2. Extract the downloadable website ZIP. Upload its contents to the repository root: index.html, content.js, app.js, styles.css, the assets folder, and the editor and guide files. Keep index.html at the top level, rather than inside another folder.
  3. Commit the files to main.
  4. Open Settings → Pages → Build and deployment. Set Source to Deploy from a branch, select main and /(root), then save.
  5. Wait for GitHub’s Pages deployment to finish. Use the published URL shown in the Pages settings to verify it.
Your existing repository is named portfolio-website. Publishing from that repository would normally use a project URL ending in /portfolio-website/. Create the user-site repository above to use the root address you requested. This website uses relative file paths and works at either location.

Official instructions: GitHub Pages quickstart and configure a publishing source.

If you still see a 404

Check the repository name, ensure index.html is in the selected folder on main, and review the deployment result in the repository’s Actions tab. GitHub’s 404 troubleshooting guide covers the common causes.
